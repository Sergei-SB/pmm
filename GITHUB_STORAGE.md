# Постійні спільні дані PMM

Сторінки сайту публікуються з `Sergei-SB/pmm`. Дані зберігаються окремо у приватному `Sergei-SB/pmm-data`, файл `shared_site_storage.json`. Браузери отримують дані через сервер синхронізації; ключ GitHub не передається користувачам і не записується у JSON.

Серверні змінні середовища:

- `PMM_GITHUB_REPOSITORY=Sergei-SB/pmm-data`
- `PMM_GITHUB_TOKEN`: fine-grained token лише для цього репозиторію, Contents: Read and write, Metadata: Read-only.
- `PMM_GITHUB_BRANCH=main` (необов'язково, це стандартне значення).

Початковий перевірений JSON потрібно записати в приватний репозиторій до ввімкнення змінних. Якщо репозиторій публічний, файл відсутній/пошкоджений або доступ не працює, сервер не замінює його порожньою базою. На старті GitHub є джерелом істини, локальний диск — лише кешем. Після перезапуску дані відновлюються з GitHub.

Запис підтверджується після успішного коміту GitHub. Попередні версії та час зберігаються в історії комітів. Паралельний сторонній запис не перетирається: перевіряється SHA попередньої версії. При помилці збереження клієнт залишає зміни в черзі. Після підтвердження сервер надсилає сповіщення відкритим сторінкам; звичайне опитування працює як запасний спосіб оновлення.

Кнопка «Зберегти на сайт» записує дані у спільне сховище без автоматичного завантаження файлу на комп'ютер. Ручний експорт JSON та локальна історія залишаються додатковими засобами відновлення.

Потрібно поновити доступ до завершення строку дії токена. GitHub має обмеження частоти API-запитів і розміру файлу: сервер відхиляє JSON понад 95 MiB та не підтверджує такий запис. Це потребуватиме розділення даних на файли або іншого постійного сховища при зростанні бази.

Приватні JSON, вкладені документи та ключі не можна додавати в публічний репозиторій коду.
